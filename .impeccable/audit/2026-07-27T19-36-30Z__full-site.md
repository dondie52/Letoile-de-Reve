## Detailed Findings by Severity

### [P1] Missing tour videos cause repeated 404s
- **Location:** `ASSETS.heroVideo` / `ASSETS.lifestyleVideo` → `/assets/videos/*.mp4`; `public/assets/videos/` absent
- **Category:** Performance
- **Impact:** Every visit fires failed requests (observed 2× each URL) and console errors; fallback photos work, but network noise and failed media pipelines remain
- **WCAG/Standard:** N/A (perf / reliability)
- **Recommendation:** Ship compressed MP4s under `public/assets/videos/`, or stop requesting video when assets are absent (no `<video>` / no HEAD until known-good)
- **Suggested command:** `/impeccable harden` (or `/impeccable optimize` if focusing on request hygiene)

### [P1] Apartment room tabs undersized (~27×64–95px)
- **Location:** `ApartmentShowcase.tsx` room `role="tab"` buttons
- **Category:** Accessibility / Responsive
- **Impact:** Harder to activate precisely on touch/trackpad; fails the audit’s 44×44 guideline (passes WCAG 2.2 AA 24×24 minimum)
- **WCAG/Standard:** 2.5.5 Target Size (AAA); audit checklist 44×44
- **Recommendation:** Increase hit area with `min-h-11` / padding while keeping the visual nav-label weight
- **Suggested command:** `/impeccable adapt`

### [P1] Footer & booking contact links short hit height (~19–22px)
- **Location:** `Footer.tsx` nav links; `BookingFinale.tsx` / `Footer.tsx` `.contact-line` anchors
- **Category:** Accessibility / Responsive
- **Impact:** On mobile, phone/email/footer links are easy to miss; slows the booking path
- **WCAG/Standard:** 2.5.5 Target Size (AAA); audit 44×44
- **Recommendation:** Add vertical padding (`py-2` / `min-h-11`) on contact and footer links without changing type roles
- **Suggested command:** `/impeccable adapt`

### [P2] Global `prefers-reduced-motion` 0.01ms kill switch
- **Location:** `src/app/globals.css` `@media (prefers-reduced-motion: reduce)`
- **Category:** Accessibility
- **Impact:** Wipes useful state feedback (button hover/focus transitions) site-wide; JS already provides intentional reduced paths for hero/gallery
- **WCAG/Standard:** 2.3.3 Animation from Interactions (AAA related guidance)
- **Recommendation:** Remove the universal `*` duration nuke; keep Lenis/GSAP reduced branches and selectively disable decorative CSS only
- **Suggested command:** `/impeccable harden`

### [P2] Tablist missing `aria-controls` / tabpanels
- **Location:** `ApartmentShowcase.tsx` desktop room tabs
- **Category:** Accessibility
- **Impact:** Screen-reader users get selected state but weaker panel association for the active room copy/image
- **WCAG/Standard:** ARIA Tabs pattern; 4.1.2 Name, Role, Value
- **Recommendation:** Wire each tab to a panel id (`aria-controls` + `role="tabpanel"`) or drop tab roles for a simpler button list if panels aren’t discrete
- **Suggested command:** `/impeccable harden`

### [P2] Required fields only enforced in JS
- **Location:** `BookingFinale.tsx` inputs (no `required` / `aria-required`)
- **Category:** Accessibility
- **Impact:** Assistive tech and browsers don’t announce fields as required before submit; recovery exists via alerts after submit
- **WCAG/Standard:** 3.3.2 Labels or Instructions
- **Recommendation:** Add `aria-required="true"` (and optionally native `required` with careful date UX)
- **Suggested command:** `/impeccable harden`

### [P2] Hard-coded gradient / star-field colors
- **Location:** `Hero.tsx` overlay `bg-[linear-gradient(...)]`; `globals.css` `.star-field` `rgba(...)`
- **Category:** Theming
- **Impact:** Drift risk if palette tokens shift; not user-facing today
- **Recommendation:** Express overlays via `color-mix` on `--forest` / `--gold` / `--ivory`
- **Suggested command:** `/impeccable colorize` or `/impeccable document` after cleanup

### [P2] Persistent `will-change` on room images
- **Location:** `ApartmentShowcase.tsx` `will-change-transform` on every `[data-room-image]`
- **Category:** Performance
- **Impact:** Extra compositor layers for four full-bleed images even when idle
- **Recommendation:** Apply `will-change` only while the pin timeline is active, then clear
- **Suggested command:** `/impeccable optimize`

### [P3] Experience section has no `id`
- **Location:** `VideoExperience.tsx` `<section>` (labelled, not in primary nav)
- **Category:** Implementation Integrity
- **Impact:** Cannot deep-link; low severity because section isn’t in `NAV_LINKS`
- **Recommendation:** Add `id="experience"` if you want shareable anchors
- **Suggested command:** `/impeccable polish`

### [P3] Logo home control ~40px tall
- **Location:** `Navigation.tsx` logo link (`h-10`)
- **Category:** Responsive
- **Impact:** Slightly under 44px height; width is ample (~157px)
- **Recommendation:** Optional `min-h-11` wrapper padding
- **Suggested command:** `/impeccable adapt`

### [P3] `images.unoptimized: true` in Next config
- **Location:** `next.config.ts`
- **Category:** Performance
- **Impact:** Expected for static export; assets are already lean WebP (~4–127KB). Not a defect if GH Pages/static hosting remains the target

- **Suggested command:** `/impeccable optimize` only if hosting model changes

## Patterns & Systemic Issues

- Touch targets for **text-style links** (footer, contacts, room tabs) consistently favor visual quiet over 44×44 hit areas — systemic for this editorial UI, needs intentional padding strategy.
- Media pipeline assumes optional videos but still **probes and mounts** them when absent — systemic request hygiene gap.
- Reduced-motion is handled twice (JS intentional + CSS global kill) — simplify to one coherent strategy.
